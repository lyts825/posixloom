# 优化实施与验收记录

本文把本轮优化清单映射到可检查的实现与门禁。它记录的是完成状态与验证方法，
不是未来版本的性能或恶意软件零风险承诺。

## 第二阶段：公开入口、Shell 隔离与真实负载

- 公开 EXE 命令统一进入完整性校验后的 CLI，保留 `launch` 兼容入口；内部执行
  协议仅由 `__exec-host --protocol-v1` 启用。stdio 使用已构建的独立入口，构建
  提示写入 stderr。真实子进程握手测试覆盖帧边界与精确 argv。
- SDK 补齐 ESM exports、类型声明和嵌入示例；测试把实际 npm tarball 安装到
  独立、离线的消费者目录，再进行类型检查和执行，避免依赖仓库相对导入。
- isolated Shell 用 Bash builtin 输出最小完成回执，省去 cwd/环境采集和相应
  外部进程；cwd-env 继续使用完整 StateReport。提前 exit、exec、errexit、
  回执损坏和取消仍保留各自的失败语义。
- 验证发现同一安装的 MSYS DLL 会共享挂载表。Windows Shell 现要求支持
  `shell-namespace-v1` 的 Native Host，按实际 DLL 和用户身份跨进程互斥，
  覆盖命令执行、整个后代进程树清理和崩溃恢复。等待支持取消/超时，Native
  argv 继续并发。Git 包装入口与直接 Bash 入口使用同一身份。外部 MSYS 进程
  不参与互斥，固定 `/tmp` 不匹配时明确失败；完整包包含独立的 MSYS 安装。
- HTTP 仅允许尚未准入的过载请求用同一幂等键重新尝试，已准入的失败仍保存
  回执；普通 JSON、NDJSON 与重放均等待实际写入/结束，有排空期限和断连清理。
  OpenAPI 增加完整响应结构，并用真实服务响应验证契约。
- GUI 历史输出限制为 1 MiB UTF-8、256 个节点和 2000 个换行，按帧批量渲染，
  保留向上阅读位置并提供回到最新。NDJSON 按字节分帧，超限、乱码和损坏帧
  会取消读取及请求；真实 Edge 已验证持续输出、滚动和坏流断连。
- 性能报告升级为 schemaVersion 2，区分直接 Node CLI、公开 Launcher、复用
  Service 三种路径，加入真实进程/HTTP 64 MiB 输出和并发负载。候选包测量
  强制使用包内 Node、模块与资源，保存包清单摘要，检查输出和成功完成。
  Windows 10/11 发布工作流要求两台机器验证相同的候选清单哈希。

## P0：安全性、容量与有界状态

- StateReport 改为随包分发的可读 Shell 资源，更新 ZIP 解压改为静态 PowerShell
  资源；两者都进入发布清单和 SHA-256 覆盖，打包测试会篡改资源并确认 Launcher
  拒绝启动。MSYS 初始化先接收真实宿主临时目录，进入 Shell 后才恢复 `/tmp`，
  覆盖不同盘符和全新工作区。
- 一个 Runtime 内的嵌入式 Service、HTTP 与 stdio 共用执行调度器。全局/客户端
  并发、等待队列和排队超时均可配置；同会话顺序执行不会占住空闲槽，排队取消
  会立即回收容量，过载返回稳定的 `SERVER_BUSY` 或 `QUEUE_TIMEOUT`。
- 执行中和排队中的操作（包括 isolated 与 preview）持有会话租约，空闲回收和
  显式关闭不会破坏其状态。stdio 的活动请求 ID 永不被淘汰，完成 ID 受数量与
  TTL 双重限制；传输层另有限制并为取消、关闭和终端控制保留容量。

## P1：诊断、协议与故障隔离

- 执行和预览在校验阶段即创建遥测，失败路径也记录；配置、初始化、排队、准备、
  策略、后端启动/首字节/退出、完整性复验和状态提交均有单调时钟阶段数据。
  默认不采集命令名，始终不记录参数、Shell 正文、环境值或绝对路径。
- 内存 trace 是固定容量环；文件 writer 有待写字节上限、批处理、轮转与保留上限。
  序列化、磁盘和接收器错误只进入诊断计数，不改变命令结果；关闭会有界刷盘。
  同进程同路径写入被串行化，独立进程应使用不同 DataRoot 或集中日志系统。
- CLI、HTTP 与 stdio 共用同一执行请求解析器和 UTF-8/结构上限。HTTP 发布
  JSON Schema 与 OpenAPI 3.1；流式请求在首个事件前不提交 200，因此预检和准入
  错误仍有正确状态码。
- HTTP 的 `Idempotency-Key` 以规范化请求指纹保护有副作用的重试：在途、冲突、
  满容量、超大回执和已完成重放具有不同结果。回执受数量、TTL 和字节数限制，
  不会因为结果没保存而重新执行；保证仅限当前进程生命周期。
- HTTP 与 stdio 的输出均传播背压并有排空期限。客户端断开或服务关闭会取消关联
  进程树、等待请求收束并刷盘；所有终态仍保持单一完成语义。

## P2：结构、性能与工程门禁

- Rust Native Host 已拆为协议、worker、Unix 执行、launcher 与 Windows 执行/
  pipe/PTY/resource 模块。Windows 进程、管道、Job 与 ConPTY 资源使用所有权封装，
  子进程先挂起、加入 Job 后再恢复，取消/超时覆盖后代进程。
- TypeScript 的进程后端、更新器和 CLI 被拆为职责明确的模块，同时保留公共导出。
  输出收集器使用固定容量头尾缓冲，帧解码按声明长度单次分配并线性复制。
- 开发模式 PATH 查找直接探测文件系统，不再为每次冷查找启动 `where.exe` 或
  `which`；缓存包含 cwd/PATH/PATHEXT，发布模式仍只使用清单固定入口。
- `trace summary` 给出原生命中率、阶段分位数、失败阶段和显式开启的简单命令名
  候选。候选按观测累计执行时间排序，但不把命令耗时误报为可节省的 Shell 成本；
  新原生适配器必须先经过真实负载与语义等价性验证。
- 测试被拆为 unit/integration，并加入并发、取消、容量、重放、幂等、断连、关闭、
  trace IO 故障、输出环、Unicode/分片/畸形帧和临时盘符等回归。Windows CI 覆盖
  Node 22/24、Rust fmt/Clippy/test 与性能预算；独立发布工作流覆盖干净 Win10/11。

## 外部发布边界

代码库已提供强制本机扫描和 `release-defender-client-gate`。本轮没有可用的独立
干净 Windows 10/11 自托管机器，因此尚未产生那两台机器的运行证据。正式分发前
必须把完全相同的候选包暂存到两台一次性客户端，运行该手动工作流并保存报告；
本机通过不能替代这个发布门禁。具体操作见[发布与更新指南](release.md)。
